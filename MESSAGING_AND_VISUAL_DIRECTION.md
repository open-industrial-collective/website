# OIC message and visual direction

Founder-reviewed direction, September 30, 2026. This guide governs the public site's introductory copy and decorative artwork. It does not change the Listing Charter, project licensing, or the scope of OIC's current review.

## The public promise

**One sentence:** OIC helps builders share free industrial software and helps industry access, assess, and adopt it.

**Homepage:** Free industrial software. More room to innovate. OIC helps builders bring free tools to industry, so more teams can try new ideas and solve real problems.

OIC exists to lower economic and discovery barriers between useful industrial ideas and real-world use. The catalog is an initial mechanism. Builder participation, practical disclosure, and evidence shaped by industrial expertise are the broader mission. Build → Share → Prove is the long-term model; scoped evaluation work is still in development.

Use **projects** for catalog entries, **software** for the umbrella offer, and **tool** when it accurately describes a particular project. One project may offer several delivery formats, such as a browser app, source archive, container, module, or service endpoint. Do not call each package a separate project by default.

Every listed edition has a genuine way to use it for free. Open source, source available, and closed source describe different rights. Required commercial hosts, hardware, accounts, services, integration, and support may have separate costs. State those requirements beside the free claim. Catalog admission is a human review of listing information; it is not software certification, independent verification, or production approval. When evidence exists, name its subject, scope, reviewer, conditions, and limits.

## Visual grammar

The founder's September 30 isometric industrial workbench image is **art direction**, not a page graphic. The site uses separate text-free illustrations based on its 3/4 camera, ivory bases, graphite panels, restrained rust-orange connections, tactile materials, and soft depth. Keep headings and labels as HTML. Use the OIC mark as branding, not as a substitute for the industrial scenes. Product screenshots remain the primary proof of each project's appearance and capabilities; decorative OIC illustrations never represent a publisher's actual product.

The seven generated assets in `public/images/illustrations/` are: `workbench-hero.webp` (Home), `build.webp`, `share.webp`, `prove.webp` (Why OIC), `community.webp` (Community), `profile.webp` (How It Works, Share, Guide), and `platform.webp` (Platforms). Explore uses actual screenshots, with illustration only for its empty state. Project pages, the Charter, and Safety use quiet code-native linework. All generated art is decorative with empty alt text; copy carries the meaning. Assets are WebP with alpha and lazy loading except the Home hero.

Generation mode: built-in ImageGen, using the founder-supplied workbench as an art-direction reference. Prompts requested standalone isometric industrial modules in the shared palette: a connected robot/conveyor/tank/software hero; robot and screen for Build; linked modules for Share; machine plus inspection notebook for Prove; joining modules for Community; separate tool and profile sheet for sharing; and a free component linked to a larger host for Platforms. All prompts excluded text, logos, brands, badges, watermarks, and certification claims.
